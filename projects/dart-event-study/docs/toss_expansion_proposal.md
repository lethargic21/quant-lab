# 토스 커버리지 확대 제안서 (Phase 4 — 제안만, 실행은 승인 후)

> 2026-07-25. 순방향 수집이라 **지금 안 늘린 종목의 과거분은 영원히 못 만든다.** 향후
> 검정력 = 종목수 × 수집개월 × 이벤트발생률. 이 문서는 근거·부하·리스크를 제시하고
> 단계적 확대안을 제안한다. **toss_universe.yaml은 승인 전까지 건드리지 않는다.**

## 1. 핵심 발견 — 현재 유니버스가 신호와 어긋나 있다

현재 20종목은 커뮤니티 **활성도**(개인 관심 상위)로 뽑혔다. 그런데 이 레포의 **유일한
강건 신호는 자사주 드리프트**다. DART 실측(2019–2024, 7년) 결과 둘이 거의 겹치지 않는다:

| 지표 | 값 |
|---|---|
| 현재 20종목의 자사주 이벤트 총계 | **41건 / 7년 → 연 5.9건** |
| 그중 셀트리온 1종목 | 16건 (39%) |
| 자사주 이벤트 **0건**인 종목 | 20종목 중 **12종목** (SK하이닉스·카카오·에코프로·알테오젠·LG엔솔 등) |
| 향후 12개월 예상 자사주 이벤트 | **~6건** |

즉 현재 구성으로는 앞으로 1년간 **분석 가능한 자사주×어텐션 관측이 6건 남짓** 쌓인다.
검정력이 나오지 않는다. 활성도 최적화가 신호 최적화와 어긋난 결과다.

## 2. 확대 후보 — 자사주 빈발 & 현재 미포함 (KOSPI200 우선)

DART 자사주 이벤트 빈발 종목 중 현재 유니버스에 없는 상위:

| 종목 | 코드 | 자사주(7년) | 연 |
|---|---|---|---|
| NHN | 181710 | 12 | 1.7 |
| 신영증권 | 001720 | 11 | 1.6 |
| 신한지주 | 055550 | 11 | 1.6 |
| 메리츠금융지주 | 138040 | 10 | 1.4 |
| 미래에셋증권 | 006800 | 10 | 1.4 |
| 메리츠화재 | 000060 | 8 | 1.1 |
| 현대모비스 | 012330 | 7 | 1.0 |

상위 10종목만 추가해도 연 자사주 이벤트가 **~6 → ~18건(3배)**로 뛴다.

### ⚠️ 상충 (정직 고지)
자사주 빈발 종목은 **금융·가치주**에 몰려 있다. 이들은 현재 유니버스의 성장·테마주
(에코프로·알테오젠)보다 **토스 커뮤니티 활성도가 낮을 가능성**이 크다. 즉 이벤트 수는
늘지만 종목당 어텐션 밀도는 얇아질 수 있다. → 확대 전 **커뮤니티 렌더 여부·밀도를 1회
크롤로 실측**하고, 글 0~소수인 종목은 제외한다(빈 커뮤니티는 관측 자원 낭비).

## 3. 크롤 부하 예산 (실측 기반)

| 항목 | 현재(20종목) | +10(30) | +15(35) |
|---|---|---|---|
| 1회 크롤 소요 | 404s (~6.7분) | ~10분 | ~12분 |
| 하루 크롤 수(4슬롯) | 80 | 120 | 140 |
| 종목당 HTTP 응답 | ~330 | 동일 | 동일 |
| 하루 총 HTTP | ~26k | ~39k (1.5×) | ~46k (1.75×) |
| ExecutionTimeLimit 여유 | 3h ≫ 12분 | 충분 | 충분 |

- **순간 요청률은 안 오른다** — 종목 간 2.5초 간격 + 페이지당 9초 대기가 그대로라, 종목을
  늘려도 *동시* 부하가 아니라 *실행시간*이 길어질 뿐. soft-403 리스크는 일일 총량에 비례하되
  스로틀이 완화한다.
- **관측된 soft-block 신호**: Phase 1 계측에서 매 종목 HTTP **490 1건**씩 잡힘(비표준 코드,
  토스 추정). 현재는 실패를 안 내지만, 확대 시 490 총량을 워치독/원장에서 추적해 **증가 추세면
  확대 중단**. 이게 계량 가능한 안전판이다.

## 4. 단계적 확대안

1. **Stage 1 (승인 시 즉시)**: 위 상위 후보 중 커뮤니티 밀도 실측 통과분 **~10종목 추가 → 30종목**.
   연 자사주 이벤트 ~6→~18건. 크롤 ~10분/슬롯, 부하 1.5×. 순방향이라 **빠를수록 과거분 축적 이득**.
2. **Stage 2 (1–2주 안정 확인 후)**: ok-rate·490 추세 정상이면 **+10 → 40종목**. 실적·유증
   이벤트까지 고려하면 종목당 연 이벤트가 더 늘어 검정력 개선.
3. **모니터링 게이트**: 매주 `toss-ledger`로 ok/partial/missing 추세 + run 로그의 490 총량 확인.
   partial/미싱이 늘거나 490이 급증하면 확대 롤백. 확대는 **건강 지표가 초록일 때만** 전진.

## 5. 실행 시 변경 지점 (승인 후)
- `config/toss_universe.yaml`의 `expand:`에 종목 추가(코드·이름). additive — 기존 20종목 데이터 불변.
- 각 신규 종목 커뮤니티 렌더·밀도 1회 실측 후 최종 확정(빈/저밀도 제외).
- 유니버스 변경 이력을 이 문서에 기록. 스케줄러·부하 설정 변경은 없음(종목만 늘어남).

**요약**: 지금 구성은 향후 12개월에 자사주 관측 ~6건뿐 — 신호와 어긋났다. 자사주 빈발
KOSPI200 종목(금융·가치주)으로 단계 확대하면 이벤트 수율이 3배 이상 오르나, 커뮤니티
밀도 상충을 실측으로 걸러야 한다. 부하는 실행시간만 늘 뿐 순간 요청률·ExecutionTimeLimit엔
여유. 490 soft-block 총량을 게이트로 단계 확대. **승인 후 toss_universe.yaml만 수정.**
